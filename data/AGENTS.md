# data

## Purpose

The catalog source of truth and its generated lookup index.

## Ownership

`catalog.json` is the only place an entry is authored. `search-index.json` and the `entries/<slug>/index.html` pages are generated by `tools/build.py` and must never be hand-edited.

## Local Contracts

- `catalog.json` is a JSON array of entry objects. Required fields: `slug`, `name`, `type`, `author`, `summary`, `description`, `status`, `tags`, `where_to_find`, `how_to_use`, `config_snippet`, `setup_prompt`.
- `slug` is lowercase `[a-z0-9]+(?:-[a-z0-9]+)*` and unique.
- `type` is one of `scorer`, `modifier`, `config`, `model`, `fork`, `tool`.
- `status` is one of `available`, `community`, `proof-of-concept`, `planned`.
- `where_to_find` is a non-empty array of `{ label, url }` with `https://` URLs or local relative paths.
- `setup_prompt` is written for a coding model with no Heretic context. It must name the plugin, the file path or model ID, the config keys, and a verification step.
- A site-relative `where_to_find` URL must resolve to a real file in the repository; `tools/build.py` enforces this.
- Entries describe community or non-default material only. Built-in default scorers are documented in `docs/HERETIC_PLUGINS.md`, not catalogued as entries.
- Links and instructions for shipped plugin sources use the `plugins/` prefix; the setup prompt then tells the user to copy that file into their own Heretic working directory.
- Provenance is factual. Do not invent links, benchmarks, licenses, or authors. If a source was only discussed in chat, say so in `status` and link the discussion.

## Work Guidance

- Add one entry per plugin or artifact. A family of related entries may link each other by slug.
- Keep `summary` to one sentence under 160 characters; it is what the catalog list shows.

## Verification

- `python3 tools/build.py --check` validates schema, slugs, links, and prompt presence.
