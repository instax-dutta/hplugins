LLM Judge scorer

/scorer - by kurigohanandkamehameha - proof-of-concept

Uses a separate language model to decide whether a response actually complies, instead of matching refusal keywords.

What it does

A pull request that sends responses to a judge model through an OpenAI-compatible API and classifies them. It was motivated by thinking models that refuse inside the reasoning trace and by unusual refusal formats that keyword lists miss. The author found that running the judge as an external API client worked better than loading it inside the Heretic process.

Where to find it

  • Plugin system PR discussion
  • Mainline scorer interface

How to use it

  1. Check whether the LLM judge PR has been adapted to your Heretic version; the plugin interface changed between 1.x and 2.x.
  2. Configure a reachable OpenAI-compatible endpoint and a judge model with enough context for the full response.
  3. Register the judge scorer with optimization = minimize so judged refusals go down.
  4. Compare its verdicts against KeywordRate on a small response sample before a long run.

Config fragment

scorers = [
    { plugin = "./llm_judge.py:LLMJudge", optimization = "minimize" },
    { plugin = "heretic.scorers.kl_divergence.KLDivergence", optimization = "minimize" },
]

Setup prompt

Add an LLM-based refusal judge to my local Heretic setup. The approach comes from kurigohanandkamehameha's PR: responses are classified by a separate model through an OpenAI-compatible API, which helps with thinking models whose refusals appear in the reasoning trace. First check my Heretic version and whether an adapted judge plugin exists; the plugin interface changed between 1.x and 2.x. Configure the endpoint and model from my environment, register the judge scorer with optimization = minimize, and keep KLDivergence minimizing. Do not hardcode any API key. Verify by judging a small sample of responses and comparing the verdicts with KeywordRate before starting a full run.
